PLATFORM CONFIGURATION

SMS providers.

Provider routing for BJVERIFY. API credentials must remain server-side.

United States providers

The dedicated USA tab uses TestVerified. In All Countries, Server 1 uses FetchSMS for USA. Do not confuse these two routes.

Fetch SMS

Used for USA inside All Countries → Server 1. USA-only non-VoIP short-term verification service; rental endpoints are excluded.

UNITED STATES

Required secret: FETCHSMS_API_KEY.

TextVerified (Test Verified Virtual SMS)

Used by the dedicated USA tab. This route remains separate from All Countries → Server 1.

UNITED STATES

Required secrets: TEXTVERIFIED_API_USERNAME and TEXTVERIFIED_API_KEY.

Server 2 · SMSBower

All Countries → Server 2 uses SMSBower pool inventory. Manage server visibility, services, visible pool limits, individual pools and server/pool prices in SMS Board Management.

International provider

Server 1 uses VirtualSMS for countries outside the United States. USA is routed to FetchSMS.

VirtualSMS (Virtual Number)

International country inventory. Country and service catalogues must come from its live API.

INTERNATIONAL · EXCLUDING USA

Required secret: VIRTUALSMS_API_KEY.

Security and setup

Do not paste API keys into this page or commit them to GitHub. Add the four provider secrets in the BJVERIFY Supabase project under Edge Functions → Secrets. Open BJVERIFY Supabase function settings. The provider catalogue and order functions are deployed; live provider inventory and purchases will work after the relevant credentials are saved.
