PLATFORM CONFIGURATION

SMS providers.

Provider routing for Sparkle SMS. API credentials must remain server-side.

United States providers

Both providers can contribute USA inventory to the USA and all-country search results.

Fetch SMS

USA-only non-VoIP short-term verification service. Rental endpoints are intentionally excluded.

UNITED STATES

Required secret: FETCHSMS_API_KEY.

TextVerified (Test Verified Virtual SMS)

USA provider route. Confirm the exact provider API host and account API contract before enabling live orders.

UNITED STATES

Required secrets: TEXTVERIFIED_API_USERNAME and TEXTVERIFIED_API_KEY.

International provider

Used for countries outside the United States. USA must not be requested from this provider.

VirtualSMS (Virtual Number)

International country inventory. Country and service catalogues must come from its live API.

INTERNATIONAL · EXCLUDING USA

Required secret: VIRTUALSMS_API_KEY.

Security and setup

Do not paste API keys into this page or commit them to GitHub. Add the four provider secrets in the Sparkle Supabase project under Edge Functions → Secrets. Open Sparkle Supabase function settings. The provider catalogue and order functions are deployed; live provider inventory and purchases will work after the relevant credentials are saved.
